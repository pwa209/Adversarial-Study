# Native nine-population data qualification

This shared loader supports the full-population observation-map comparison and the finite-amplitude perturbation analysis. It adds no human data, retraining, simulated subjects or physiological identification. The study's 42-person behavioural target and the prerequisite for both real human-data fine-tunings are enforced by the deployment driver before these consumers execute.

The source is the existing native bank, bound to its SHA256-pinned inventory and bank receipt. Every finite row is matched to its canonical `simulations/<simulation_id>/native.output` and colocated `configuration.conf`; both hashes must match the original inventory. Simulation IDs retain the original pristine versus explicitly patched implementation. A provenance mismatch stops the analysis. Original execution failures remain in the disposition table. Numeric/schema exclusions are explicit and cannot silently remove a required simulation.

The parser requires the exact standalone 45-character configuration/data separator, the native column names, and one node for every output. It checks all numeric columns for finiteness and requires the 5,000 actual native time labels from 0.002 through 10.000 s, inclusive, at 2-ms intervals. These labels are retained exactly; they are relative to the configured output start. The first recorded observation occurs one output interval after that start. The former 0–9.998 s requirement was incorrect and excluded the actual files. The corrected loader rejects a zero-origin clock rather than subtracting 0.002 s or shifting the data. It preserves the nine endogenous populations' voltages and firing rates as 18 distinct observed columns. Population 10 is the observed noise input; population 11 is the rectangular perturbation input when physically output. Neither is counted as a neural population. No interpolation, padding, synthetic replacement or output-time extrapolation occurs in this loader.

Configuration metadata include the actual population names, one spatial node, input timing, integration/output clocks, all 41 configured coupling/dendrite/propagator entries and their source/destination populations. The 41 entries include external-input connections; this count is not represented as 41 internal neural connections. These configuration parameters are not a Jacobian, a validated whole-brain connectome or the complete dynamical stability spectrum.

For perturbation pairing, the loader requires matched implementation, family, parameter factors and pair ID. Control and pulse configurations may differ only in Population 11 amplitude, with an additional WhiteSeed metadata difference allowed only when the complete observed Population 10 noise stream is exactly identical. All 18 neural traces must match before the intervention within the declared numerical tolerance (absolute tolerance `max(abs(control baseline in that column),1) × 1e-10`, separately for each column). Both actual Population 11 outputs must be present; the control is zero, the positive pulse agrees with its configured amplitude and timing, and no input occurs outside the pulse window. Relative onset is calculated from configured absolute onset minus configured output start: 12 − 10 = 2 s, without a 0.002-s adjustment. This puts the onset at index 999 of the preserved native clock. These are finite-amplitude model interventions, not validated linear impulse responses or human causal effects.

The scheduled worker performs the raw bank read once. A successful qualification produces four aggregate files: a compressed NPZ array cache, a JSON configuration/identity table, a CSV containing every inventory disposition, and a receipt pinning those three outputs. All are created exclusively and never overwritten. The CSV is persisted before the required-member check, so an unsuccessful qualification retains every rejection reason. Its rejection receipt records counts and at most 20 representative error groups, with at most eight identities and 512 error characters per group. These diagnostics cannot substitute for a qualified cache. Consumers reverify aggregate hashes, shapes and the complete actual clock before reuse. The `native_nine_population_cache_v2` schema and explicit first/last time, reference and non-rebasing receipt fields prevent reuse of a former zero-origin cache. This avoids creating one cache file per simulation. The expected 664 × 5,000 × 18 array contains approximately 60 million float64 values; inputs are stored separately, within the requested 64-GiB memory budget. Full-bank and full-cache reads require a Slurm job ID. Unit tests use expressly synthetic fixtures and establish parser/provenance behaviour only; the scheduled qualification additionally checks actual source files.

## Consumer API

`load_bank(inputs, cache_dir, seed=20261024)` creates and returns `{'traces': {simulation_id: trace}, 'rows': all_dispositions, 'receipt': receipt, 'cache_dir': path}`. `read_cache(cache_dir)` returns the same structure without reparsing native files. `run(inputs, cache_dir, seed)` returns its receipt. The driver passes SHA256-pinned `bank_inventory`, `bank_receipt`, and `scored_bank` roles, either directly or under `files`, plus an optional canonical `bank_root`. `required_simulation_ids` makes any missing or numerically excluded member fatal.

Each trace provides `times`, `values` (5,000 × 18, ordered V,Q within populations 1–9), `columns`, `voltage`/`V`, `rate`/`Q`, `noise`/`noise_Q`, `stimulus`/`perturb_Q`, `stimulus_observed`, `row`, `config`, and `config_text`/`configuration_text`. `qualify_pair(control, pulse)` returns the actual pairing proof including relative onset, width and amplitude or raises an error. `load_native(row, allowed_root)` is the per-output parser/provenance helper. Aliases `load_population` and `load_cache` preserve the same contracts.
